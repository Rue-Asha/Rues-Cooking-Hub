## Context

Rues Cooking Hub moves from its own light warm look (local `tokens.css`/`global.css`, Fraunces + DM Sans, glass pill nav, bento Home) onto the shared Design-System fingerprint 1.0.0, and its phone navigation gains search, add and a context "+". This change runs gates 3–8 of the ecosystem pipeline (`Design-System/openspec/changes/ecosystem-ui-revamp`, tasks 9–11): gate 3 is `scope.md` (signed off 2026-11-15), gate 4 greyscale wireframes and gate 5 hi-fi each end with Rue's sign-off, checkpoint A (ecosystem 10) re-syncs the fingerprint, gate 6 builds the UI layer only, gate 7 is flow's Verify and gate 8 is Ship (`ship: merge`, `release: tag` → v0.4.0).

Constraints that shape the plan:
- UI layer only (ecosystem 11.1). Every `+page.server.ts`, `+server.ts`, `src/lib/server/**`, schema and migrations stay. Screen Wake Lock is client-only. The functional-contract edit for Eating Out (S16) is documentation.
- The sibling Notes-Archive went through the same pipeline first; its plan (`git -C ../Notes-Archive show flow/redesign:openspec/changes/redesign/{tasks,design}.md`) is the template, and its learnings are folded in below (slop baseline, icon links after the first sync, comma-joined token lists, `.stage` collisions, Frame owner before parallel hi-fi units, family moves per surface up front).
- `proof` and `proof:full` runs are serialized across apps; this repo's port range is 475x (Notes 47xx, Life 472x, Creative 473x and the ecosystem orchestrator 474x are taken): the orchestrator's own runs use 4750, and within a wave the builders take 4751, 4752, 4753 in the order tasks.md lists them.
- `graphify-out/graph.json` exists: every unit runs `graphify query "<question>"` before its first grep or source read; `graphify update .` runs only in the last build unit (23.5), so parallel branches don't conflict on `graph.json`.
- The Design-System specimen already holds Cooking screens: `Design-System/specimen/cooking-list.html`, `cooking-plan.html`, `cooking.css`, and the recipe tile of `brief/round-4/`. They are the hi-fi starting point, not a cage.

## Goals / Non-Goals

**Goals:** S1–S18 of `scope.md`: shell and navigation (top bar, phone bar, context "+", Home choice sheet, recipe actions everywhere, guard), every screen in the inventory on the fingerprint with all contract states, keep-awake on the recipe page, Eating Out carried along and added to the contract, WCAG 2.2 AA and English copy, the master icon, and the cleanup of the old styling.

**Non-Goals:** as in the proposal: no Eating Out redesign (IA, cards, list), no cook-view features beyond keep-awake, no server/load/action/migration change, no global search across recipes and spots, no dark mode.

## Risks / Trade-offs

- [Transitional look between waves: old screens render with fingerprint roles over old tokens] → accepted; gate 6 is judged after the last build wave; e2e asserts behaviour, not visuals.
- [Baseline filter hides a regression in a not-yet-rebuilt file] → keyed by declaration text, so a new or changed declaration fails; Verify also runs bare `check-slop` and reports what is left; U23 removes the baseline.
- [Five pills + "+" don't fit at 320 px (R1)] → superseded at checkpoint A (2026-11-16, fingerprint 2.0.0): pills are icon-only below 360 px and labelled from 360 px.
- [Hi-fi units drift from the family] → the Frame owner (U7) runs before U8/U9, and every hi-fi brief carries "Family moves per surface".
- [Wake Lock differs by browser] → feature-detected, errors swallowed, proven with a stub in e2e and on Rue's phone at gate 7.
- [Checkpoint A slips] → the build waits (group 12); gates 4–5 don't depend on it.
- [A primitive needs a change in a later wave] → the builder reports it, the orchestrator applies it between waves; fingerprint changes go to Design-System `requests.md`.
